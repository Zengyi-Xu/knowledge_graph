## 1. 目标

1. **写代码出图**：在笔记里写一段代码（流程图的 DSL），自动排版成图，不手动拖节点。
2. **紧凑但不拥挤**：节点顺序由布局算法决定；节点间距、折线走线、边标签避让都按规则算出来。
3. **好看**：字号/行高/圆角/留白成套；配色跟应用主题（浅色莫兰迪，深色同步），保证正文对比度。
4. **可保存、可分享**：图跟着笔记的 Markdown 走（fenced code block），能导出 SVG/PNG，离线可用。

## 2. 非目标

- 不做自由画布（拖拽节点、随意连线）——那会带来「每次打开都可能不一样」的布局，和笔记的可复现性冲突。
- 不追求 Mermaid 全语法；只做流程图/泳道图够用的一层子集。
- 不做在线协作/评论。
- 不引入联网 CDN 渲染（本应用的核心约束是离线）。

## 3. 语法：Mermaid 兼容子集

选 Mermaid 子集的理由：用户已经会，LLM 生成的质量最好，未来想升级到真 Mermaid 也有迁移路径；
但**渲染器自己实现**（体积与排版可控，见第 4 节选型）。

````markdown
```flow
flowchart LR
  A[开始] --> B{有 PDF?}
  B --是--> C[打开 PDF]
  B --否--> D[按标题兜底匹配]
  C --> E((结束))
  D --> E
```
````

支持的范围（P0 + P2）：

| 语法 | 含义 |
| --- | --- |
| `flowchart TD` / `LR` / `BT` / `RL` | 布局方向 |
| `A[文本]` `A(文本)` `A((文本))` `A{文本}` `A[(文本)]` | 矩形 / 圆角 / 圆 / 菱形 / 数据库 |
| `A --> B` `A --- B` `A -.-> B` `A ==> B` | 实线箭头 / 无箭头 / 虚线 / 粗线 |
| `A -->|文本| B` 或 `A --文本--> B` | 边标签（带底色的白底线，压在折线上） |
| `A & B --> C` | 多源/多目标合并（P2） |
| `subgraph 标题 … end` | 分组框（先算子图，再当外层的一个盒子） |
| `classDef warn fill:#f4e3d7,stroke:#b08968` / `class B warn` | 配色覆盖（受主题约束，见 6.3） |
| `%%` 行 | 注释 |

容错：解析失败时**不吞内容**——保留原始代码块并在下方给出错误行号与原因（与公式错误的处理一致）。

## 4. 布局算法（自研，不引第三方布局库）

采用分层（Sugiyama）布局，流程图的正确打开方式；实现量约 300–400 行纯函数，可离线单测：

1. **建图**：节点按声明顺序编号（保证同一份代码每次布局一致）；环用 DFS 找后向边，临时反向，
   渲染时箭头方向还原（布局第 5 步再绕回）。
2. **分层**：最长路径分层 + 源点对齐；相邻层最小间距按该层是否有边标签动态加高（标签 22px）。
3. **层内排序**：重心法（barycenter）上下各扫 4 轮，同分时按声明顺序稳定排序；目标是最少交叉。
4. **坐标**：优先级法（priority method）从左到右分配横向位置；同层节点间距 40px、层间距 56px，
   长边经过的虚拟节点占位；子图先内后外（内层算完把包围盒当一个节点）。
5. **走线**：正交折线 + 6px 圆角；同一条主干上的多条边合并成一条粗线再分叉；自环画在节点右侧。
6. **紧凑化**：所有节点落位后做一次「相邻层边界收缩」——把每层包围盒向上一层靠拢到最小间距，
   再去掉虚线/无标签边的多余拐点。

约束（写进验收）：

- 边方向严格沿 rank 递增；同层不出现边。
- 节点包围盒两两不相交（间距 ≥ 24px）。
- 折线不穿过任何节点（碰撞检测，失败时回退成绕行折线）。
- 文本换行：CJK 每 12 字、拉丁每 24 字符折行；节点最大宽 220px。

## 5. 排版与配色（「字体排布、颜色优美」的具体口径）

- **字号**：节点 13px / 行高 1.35；边标签 11px；子图标题 12px 加粗、灰度 60%。
- **节点**：圆角 8px、内边距 `10px 14px`、1px 描边；菱形/圆形的文字外接框另算，避免文字贴边。
- **连线**：1.5px；箭头 8×6；边标签加 3px 白底（`--background`）打断连线，避免和线重叠。
- **配色**：默认取应用既有的浅莫兰迪色板（与图谱 `HUB_COLORS` 同一族），按节点 `class` 分配；
  深色主题用对应深色变体。文字颜色按 WCAG 4.5:1 自动黑/白二选一。
- **留白**：整图外框 16px；多层图允许 1.5× 行距的「呼吸区」——紧凑不等于贴脸。
- **测量**：用离屏 canvas `measureText` 量真实宽度（含中英文混排），不靠字符数估算。

## 6. 集成路径（不改冻结单元）

关键约束：`md-parser`（`md.ts`/`tex.ts`）与 `md-render`（`Markdown.tsx`/`markdown-base.css`）是冻结单元，
不能为了流程图解冻。**照抄公式管线的做法**（`AGENTS.md` 第 16 条）：

1. **抽取层**（非冻结，新文件 `src/lib/flowMarkup.ts`）：正文进入 `Markdown` 之前，把
   ` ```flow … ``` ` 围栏抽成 `KGFLOWPLACEHOLDER<n>END`，与代码围栏/行内代码的判定共用一套规则。
2. **渲染层**（新文件 `src/lib/flowchartRuntime.ts`，懒加载 chunk）：解析 + 布局 + 生成 SVG，
   像 `katexRuntime` 一样按需 `import()`；**没有流程图就不下载**（`test:bundle-scenarios` 断言）。
3. **水合**：阅读面板在 `PreviewContent`（非冻结）里把占位符替换成 SVG；编辑器用 MutationObserver
   在 Vditor 的围栏预览层上补渲染（与 `hydrateVditorMath` 同一模式），源码不动、序列化/撤销仍归 Vditor。
4. **入口**：编辑器工具栏加「流程图」按钮 → 弹窗（左侧代码、右侧实时预览，「插入」写回围栏）；
   笔记里已有的围栏直接显示图，点图进入弹窗编辑。

备选（不推荐）：解冻 `md-render` 加节点类型——违反「不为新功能动冻结单元」的既定纪律。

## 7. 性能与体积预算

- 懒加载 chunk 目标 ≤ 60KB gzip（解析 + 布局 + SVG 生成；不含字体）。
- 100 节点 / 150 边的布局目标 < 30ms（纯 CPU，单帧内可完成）；超过 300 节点给出提示并退化成简化渲染。
- 首屏/文献/图谱场景的预算不能变（`npm run budget:check`、`test:bundle-scenarios`）。
- 渲染结果按「代码 + 主题 + 宽度」缓存（同一段代码重复渲染直接复用）。

## 8. 导出

- **SVG**：直接下载渲染结果（保留矢量、字体用系统栈）。
- **PNG**：2× 离屏 canvas 转图，用于粘贴到 Word/PPT（与引用复制同一类需求）。
- 打印：图不跨页拆开（`break-inside: avoid`）。

## 9. 分阶段计划与验收

| 阶段 | 内容 | 验收 |
| --- | --- | --- |
| P0 | 解析器 + 分层布局 + SVG（只读渲染） | 合成 20 节点图：无重叠、rank 单调、标签不溢出、< 30ms；中英文换行正确；`frozen:check` 全绿 |
| P1 | 阅读面板水合 + 编辑器围栏预览 + 插入弹窗 | 无流程图笔记不加载 chunk；错误代码保留原文并标错；离线可用 |
| P2 | 边标签/子图/虚线/配色 class、SVG/PNG 导出 | 30 节点真实流程图截图对比；导航栏内不出现横向溢出（`test:mobile`） |
| P3 | 主题细化、点击节点跳笔记、动画（可选） | 深色/浅色两套截图；点击节点打开对应笔记 |

- `npm run test:flow`（新）：解析/布局纯函数（Node，秒级），锁住「无重叠 / rank 单调 / 稳定排序」。
- `.tmp-flow-chart/check.mjs`：无头 Chrome 真渲染，量 SVG 盒子与截图。
- `npm run budget:check` + `npm run test:bundle-scenarios`：确认懒加载与体积。

## 10. 选型对比（为什么不用现成的）

| 方案 | 体积 | 问题 |
| --- | --- | --- |
| Mermaid.js | 500KB+ gzip | 体积太大、默认样式难改成应用的排版、离线要打包；但**语法**值得兼容 |
| Graphviz WASM | 1.5MB+ | 初始化慢、字体依赖外部配置、和 CJK 排版不对付 |
| dagre | ~100KB | 只做布局，仍需自己渲染；已多年不更新，算法可借鉴不必依赖 |
| 自研（本方案） | ~60KB | 排版/配色完全可控，纯函数可测；代价是布局算法要自己写（约 1–2 天） |

## 11. 风险

- **布局质量**：分层布局对「网状图」会排得很宽；需要对 > 6 条跨层边做折行/分组提示。
- **CJK 测量**：`measureText` 依赖字体加载，首帧可能量错；用 `document.fonts.ready` 后再量并缓存。
- **可编辑性**：图是代码生成的，用户想微调位置只能通过布局提示（`direction`、子图）；不提供拖拽。
- **冻结边界**：只能走占位符水合；一旦有人图省事去改 `md-render`，会踩 `test:frozen`。
