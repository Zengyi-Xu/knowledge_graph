# v0.3.2 启动排查与交付记录

## 旧发布包

在隔离用户配置下测试本地 v0.3.0 和 v0.3.1 便携包，均未在测试等待时间内出现可连接的渲染页面。
v0.3.1 的完整运行目录可执行文件直接以 `0x80000003` 退出。
开发 Electron 44.7.0 明确报告 `install_dir_access.cc` 的 Windows AppContainer 运行目录访问错误。
项目已有 `debug.log` 还记录过 ICU 数据文件句柄无效，但该日志不能独立证明两份 release 同一根因。

为测试运行目录递归添加应用包读取权限的操作被自动审批拒绝，因此没有实施 ACL 修改。
仍未充分证明用户双击发布包时的最终根因。按用户事先授权采用本地网页端备用路线，交付可运行的浏览器入口，未重新打包 exe。

## 性能与数据保护

交接文件指出的串行读取确实存在。现在已采用普通笔记首屏、文献后台分批加载，以及 32 并发文件读/扫描；首屏不再等待全库递归 stat。
全部文献加载完成前禁止目录 flush、全库 JSON 同步与完整导入/导出，读取失败保持保护状态。
大批导入和 Zotero 分类更新由多次全数组更新改为一次批量更新，导入/合并保留文献元数据。
浏览器存储满时显式提示无法持久化；旧设置迁移失败仍保留旧值。

生产首屏 JavaScript 从约 4.12 MB 降为约 659 KB；大型引用引擎（约 2.83 MB）、PDF 和各扩展视图延后加载。
WYSIWYG 独立块约 11.7 KB。

2000 篇合成库的文件读取测试、React 页面测试与失败场景见测试输出。
隔离新 Chrome 进程至普通笔记可交互约 0.86 秒（页面自身约 144 毫秒）；测试人为暂停文献正文读取，确认文献读取不阻塞首屏。
在后台加载时编辑普通笔记，目录保存、全库同步和导出均保持挂起；恢复后只写 1 篇编辑笔记，0 文件误删，完整同步 2000 篇。
1900 篇文献的原始文件全部逐字节不变；模拟读取失败时未写任何残缺快照。
后台扫描窗口发生外部改动与本地并行修改的冲突路径均通过真实 UI 测试。
这些结果不能证明真实百度同步盘中未落地的 2000 个文件在所有条件下均满足三秒目标。
