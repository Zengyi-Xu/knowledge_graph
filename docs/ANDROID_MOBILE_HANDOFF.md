# 安卓版与手机布局适配交接

日期：2026-10-08

状态：计划与任务交接。本文不表示安卓工程或移动适配已经完成。

## 1. 目标与范围

在现有 React + TypeScript + Vite 笔记软件基础上适配手机，后续使用 Capacitor 打包安卓 APK。Windows 发行以免安装本地网页包为主，Electron 只保留兼容层；两端尽量共用界面与 Markdown 渲染逻辑。

本轮交给 DeepSeek 的工作只包含手机展示层适配，不包含安卓外壳、数据迁移、同步协议或发布。

要求：

- 手机采用列表与详情分屏切换，不把桌面多栏布局简单压缩。
- 默认预览，编辑与预览切换，不新增所见即所得编辑器。
- 平板、电脑尽量保留现有布局和操作。
- 保留现有主题、上下标、笔记链接与笔记分类能力。
- 不修改、复制或提交任何个人笔记。

## 3. 任务拆分与顺序

### DS-01：笔记列表

修改范围：`src/components/NoteList.tsx`。

- 手机搜索框、列表项和新建入口适合触摸。
- 长标题允许合理换行，不挤压图标与元数据。
- 空列表、无搜索结果和大量笔记仍可正常滚动。
- 不改变搜索、分组、选择、新建的业务语义。
- 不自行实现顶层列表/详情路由；沿用现有回调，由核心负责人接入。

验收：360px 宽时没有页面横向溢出，常用点击区域建议至少 44px，桌面列表没有明显退化。

### DS-02：编辑界面与工具栏

修改范围：`src/components/NoteEditor.tsx`。

- 保持默认预览，以及切换笔记后回到预览的现有行为。
- 手机标题、类型、等级、标签和保存状态不重叠。
- 导出、主题导入等次要操作可收进现有菜单控件，但不得删除功能。
- 保留删除确认和现有编辑保存行为。
- 编辑区和笔记链接建议列表适应小屏幕。
- 不引入新的编辑器，不改变笔记内容，不改主题存储键。

验收：360px 宽可编辑、切换预览、增删标签；长标题和多个标签不会推出屏幕。

### DS-03：正文与主题

修改范围：`src/components/PreviewContent.tsx`；必要时增加限定作用域的样式。

- 图片按容器缩放；表格与代码块局部横向滚动。
- 长链接、长连续文本不能撑宽页面。
- 手机正文留白适度，字体使用稳定字号，不按视口宽度缩放字体。
- 保留上下标、公式现有表现、引用、列表和内部链接。
- 检查默认、paper、night、vue-light、vue-night、custom 全部主题。
- 自定义主题的移动覆盖不能影响其他页面。

注意：先阅读实际实现。若正文位于 Shadow DOM，外部全局 CSS 不会自动作用于内部正文；移动样式应放在正确的样式边界内。不要凭猜测只向全局 CSS 添加规则。

验收：所有主题在手机可阅读，桌面外观保持；不得用全局 `overflow-x: hidden` 掩盖溢出问题。

### DS-04：测试与交接

- 使用人工编写的无个人信息示例测试，不使用真实笔记生成截图或测试夹具。
- 运行现有 `npm run build` 和 `npm run lint`。
- 不擅自修复无关的既有 lint 问题；区分已有问题与新增问题。
- 将修改、测试结果、未完成事项写入 `docs/ANDROID_MOBILE_DS_REPORT.md`。
- 不运行提交、推送、发布或上传安装包操作。

建议按 DS-01、DS-02、DS-03 顺序推进。它们存在共享样式和状态接口，不建议在没有隔离写入范围时同时修改。

## 4. 布局与接口约定

- 初始手机断点：宽度小于 768px；768px 及以上保留现有桌面布局，后续实测调整。
- 优先使用项目现有 Tailwind 响应式类和 Radix 控件。
- 图标沿用 lucide-react，纯图标按钮应有可访问名称。
- 不通过隐藏所有次要功能来完成适配。
- 不根据 User-Agent 判定手机，不为读取屏幕宽度添加散落的全局事件监听。
- 保持组件现有 Props。确需增加 Props 时应为可选项，并在报告中解释用途，由核心负责人确认顶层接入。
- 不同时维护两套笔记数据；移动展示层不能直接新增持久化写入。
- 不在手机上假装桌面文件同步可用，不把文件下载成功提示为跨设备同步成功。

核心负责人后续处理：顶层列表/详情导航、返回键、目录或筛选抽屉、图谱触控、安卓桥接、活动笔记存储与导入冲突。

## 5. 测试矩阵

| 环境 | 建议尺寸 | 重点 |
| --- | --- | --- |
| 小手机 | 360 x 800 | 工具栏、标题、弹窗、横向溢出 |
| 常见手机 | 390 x 844、412 x 915 | 正文、标签、列表滚动 |
| 手机横屏 | 844 x 390 | 低高度、工具栏和编辑区可用 |
| 平板 | 768 x 1024、1024 x 768 | 保留桌面布局，避免窄栏不可操作 |
| 电脑 | 1440 x 900 | 桌面样式、主题、图谱入口回归 |
| 安卓真机（后续） | 实际设备 | 软键盘、系统返回、状态栏、离线与重启 |

测试内容：

- 长中文标题、英文长单词、长链接、多标签和空笔记。
- 多级标题、列表、引用、宽表格、代码块、大图和内部链接。
- `H<sub>2</sub>O`、`x<sup>2</sup>`；检查渲染与切换主题后表现。
- 编辑后切换笔记，再打开原笔记，内容与既有保存逻辑一致。
- 菜单、Select、删除确认、主题导入和导出入口。
- 无结果搜索、关闭弹窗、取消导入等非成功路径。

使用 Playwright 或已有浏览器测试工具记录各尺寸截图、控制台错误与溢出检查。全局页面不应横向滚动，但表格与代码块允许在自己的区域横向滚动。

浏览器模拟不能证明安卓软键盘、文件权限和系统返回已经通过；这些必须在后续 APK 真机阶段验收。

## 6. 代码审查方案

### 第一关：范围与隐私

审查 `git diff --stat`、`git diff --name-only` 和实际 diff。

- 是否只修改授权文件，是否包含其他对话已有修改。
- 是否误改 `public/notes.json`、数据结构、保存逻辑或 Markdown 解析器。
- 是否引入真实笔记、截图中的个人内容、路径、凭据或签名密钥。
- 是否有不必要的新依赖、格式化全仓库或生成产物。

任何隐私泄露或保存逻辑被擅自修改，停止合并。

### 第二关：行为与结构

- 桌面和手机是否共用既有数据及回调。
- 默认预览和切换笔记的状态是否正确。
- 菜单内操作是否仍可达，删除是否仍需确认。
- 是否因条件渲染重新挂载编辑器而丢失草稿或状态。
- 是否出现重复 ID、不正确的按钮嵌套、缺少可访问名称。
- 共享 UI 与主题覆盖是否影响其他组件。

### 第三关：视觉与交互

逐项核对测试矩阵截图与交互记录：

- 页面、工具栏、弹窗与正文无非预期溢出。
- 固定或 sticky 元素不遮挡正文与操作。
- 自定义主题样式位于正确作用域。
- 长文本、表格和代码块没有通过截断掩盖内容。
- 平板与电脑布局没有被手机适配改变。

### 第四关：构建与回归

在整合后的工作区重新执行构建和 lint，不只依赖 DeepSeek 的报告。核对新增控制台错误、上下标回归、编辑保存以及全部主题。

问题分级：

- P0：个人数据泄露、大范围数据丢失。禁止发布。
- P1：保存失效、主要流程不可用、安卓启动失败。修复后再验收。
- P2：特定尺寸遮挡、主题破坏、操作无法触达。首版发布前修复。
- P3：不影响操作的细节。记录并明确是否接受。

审查结论必须写明：发现的问题及文件/行号、测试证据、未验证事项。不能只写“完成”或“看起来正常”。

## 8. 后续安卓打包阶段

1. 添加 Capacitor 安卓工程与构建脚本，沿用现有网页资源。
